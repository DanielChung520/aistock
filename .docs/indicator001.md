# Moving Average Daniel — 設計推演筆記

> 這是「Moving Average Daniel」Pine Script（`indicator001.md` 原始碼）的設計意圖還原。
> 從代碼結構、命名、註解殘留，推演作者（Daniel）約 3 年前撰寫時的想法。
> 以下推演分為「明確證據」（代碼直接顯示）與「合理推測」（從痕跡還原）兩類。

---

## 一、總體定位

這是一支**以均線動能為核心的多空切換指標**，附帶量能佐證。

用一句話概括：

> **「當短均線動能轉強、價格突破前高時做多；當短均線動能轉弱、長均線走平時離場。」**

本質是**右側交易 + 趨勢跟蹤**，不是抄底摸頂，而是等趨勢確認後介入。

---

## 二、核心元件逐段推演

### 1. 四條斐波那契均線（8 / 21 / 55 / 89）— 明確證據

```pine
len  = input.int(8)     // MA1st
len1 = input.int(21)    // MA2nd
len2 = input.int(55)    // MA3th
len3 = input.int(89)    // MA4th
```

**推演**：8、21、55、89 全部是**斐波那契數列**成員。作者刻意用黃金分割週期建構多空框架：

- **8 / 21**：短中期動能（對應一般常用的 5/10/20，但用 fib 更貼近自然節奏）
- **55 / 89**：中長期趨勢方向

四條均線的任務分工：
- `MA8`（短）→ 判斷**即時動能**（突破、斜率）
- `MA21`（中）→ 判斷**波段動能**（加速度、買賣主軸）
- `MA55 / MA89`（長）→ 判斷**趨勢背景**（多空排列分級）

**設計意圖**：用 fib 週期的階層關係，讓短/中/長動能各司其職。這是典型的「多週期均線系統」，但作者只用價格本身的均線，沒有引入其他指標。

### 2. 扣抵值（close_offset）— 明確證據 + 台股語境

```pine
lookback = input.int(8, title="扣抵數")
close_offset = ta.sma(close[lb], lookback)   // lb = lookback
```

**推演**：**「扣抵」是台股技術分析的專用語**，指「均線接下來要扣掉的價格」。`ta.sma(close[lb], lookback)` = 把收盤價往前推 8 根，再算 8 期 SMA——即「8 天後 MA8 會扣到的那個價格區間」。

**設計意圖**：
- 用十字線（`plot.style_cross` + `trackprice=true`）把「未來扣抵價」標在圖上
- 目的：**預判均線走向**。當現價高於扣抵值，未來均線會往上走（因為要扣掉低價）；反之均線會下彎
- 這反映出作者是**用「均線未來會怎麼走」來做決策**，而不是只看當下價位

被註解的實驗痕跡印證了這個思路：
```pine
// cond = low > close[lb] and close > out and ma_slope > 0
```
作者曾想用「**低點大於扣抵值**」當作買進條件之一——即「價格守住在未來扣抵區之上」，這是扣抵概念的完整應用，後來被簡化掉。

### 3. 均線斜率（MA8 / MA21 / MA55 斜率%）— 明確證據

```pine
ma8slope  = ((out  - out8pre1)  / out8pre1)  * 100   // (MA8今 - MA8昨) / MA8昨
ma16slope = ((out1 - out16pre1) / out16pre1) * 100   // 命名是16，實際是MA21
ma55slope = ((out2 - out55pre1) / out55pre1) * 100
```

**推演**：作者不滿足於「均線在價格上方/下方」，而是把均線本身**轉換成變化率（%）**，衡量**趨勢的強度**：

- 斜率 > 0 → 均線向上 → 趨勢偏多
- 斜率 < 0 → 均線向下 → 趨勢偏空
- 斜率大小 → 趨勢強弱

**注意一個命名 bug**：`ma16slope` 其實算的是 **MA21** 的斜率（`len1=21`）。這說明這支指標是**逐步演化**出來的——早期可能用 16，後來改成 21 但沒改變數名。這是重要的歷史痕跡。

### 4. 斜率加速度（ma16sGrw）— 明確證據，全指標的靈魂

```pine
ma16sGrw = ma16slope - ma16slope[1]   // MA21斜率的變化量 = 加速度
condGrwUp = (ma16sGrw > 0)
condGrwDn = (ma16sGrw <= 0)
```

**推演**：這是整支指標**最重要的概念**——作者不只看斜率（一階導數），還看**斜率的變化（二階導數 = 加速度）**：

- `ma16sGrw > 0` → MA21 的斜率正在**變陡** → 趨勢**加速**中
- `ma16sGrw < 0` → MA21 的斜率正在**趨緩** → 趨勢**減速**中

**設計意圖**：加速度比斜率更早反應轉折。作者用「加速度由正轉負」來抓**動能衰竭的頂點**，這比等均線下彎更即時。

### 5. 大量距離（result / Near Max Volume）— 明確證據

```pine
result = 0
for i = 1 to 360
    if (volume[i] > volume)
        result := i
        break
```

**推演**：往前找**最近一根成交量比今天大的 K 棒**，回傳距離（幾根之前）。

**設計意圖**：量是價格的燃料。**大量 K 棒往往是重要的支撐/壓力區**（主力進出場的位置）。作者想標出「我們離最近的大量區多遠」，作為：
- 潛在壓力參考（賣出時機）
- 潛在支撐參考（回檔買點）

有趣的是：最終買賣條件裡 `result > 5` 被註解掉了——作者**原本想用「距離大量區」當過濾條件**，但最終沒有採用（可能因為訊號太稀或回測不佳）。

### 6. 多頭排列分級（weight / A/B/C）— 明確證據

```pine
if (out >= out2) and (out2 >= out3)   // MA8 ≥ MA55 ≥ MA89
    weight := 50; weg := "A"
else if (out >= out2)                 // MA8 ≥ MA55
    weight := 25; weg := "B"
else
    weight := 0;  weg := "C"
```

**推演**：作者把均線排列分成三級：
- **A 級（50分）**：MA8 ≥ MA55 ≥ MA89 → **標準多頭排列** → 最強勢
- **B 級（25分）**：MA8 ≥ MA55（但 MA55 < MA89）→ 中期偏多但長期未跟上 → 中等
- **C 級（0分）**：其他 → 空頭或糾結

**設計意圖**：量化「趨勢背景的強度」。注意作者用**MA55/MA89 而非 MA21** 做分級——代表他認為「多頭排列」至少要中期（55）與長期（89）都站在多方才算數。

**重要痕跡**：`transprent = 50 - weight` 和 `plot(transprent)` 都被註解了。推測作者**原本想用權重控制某個視覺元素的透明度**（可能畫出背景色塊），但最終沒啟用。目前 weight 算出來是「備而不用」的狀態。

### 7. 買賣訊號 — 明確證據，全指標的結論

```pine
cond3up = close > high[1] and close > high[2]   // 突破前兩日高點

condBuy = (ma16sGrw > 0)        // MA21動能加速
     and ma8slope > 0.05        // MA8斜率微正
     and cond3up == true        // 突破前兩日高點

condSell = (ma16sGrw < 0)       // MA21動能減速
     and condGrwDn[1] == false  // 前一根還不是減速（抓「剛轉弱」那一刻）
     and ma8slope < 0.02        // MA8斜率接近走平
```

**買進邏輯還原**：
1. 價格**突破前兩日高點**（突破訊號）
2. MA8 斜率微正（短期動能還在）
3. MA21 加速度為正（波段動能正在**加速**）

→ **三層確認：價格突破 + 短動能 + 中動能在加速**

**賣出邏輯還原**：
1. MA21 加速度轉負（波段動能開始**減速**）
2. **前一根還不是減速**（`condGrwDn[1] == false` = 上一根 `ma16sGrw > 0`）→ 抓「剛從加速轉為減速」的**第一根**
3. MA8 斜率接近走平（<0.02%）

→ **賣出不看價格，只看動能衰竭**：一旦中段動能由加速轉減速，且短線走平，就離場。

**買賣的不對稱設計（重要推演）**：
- **買進**：需要價格突破（較嚴格，等確認）
- **賣出**：不需要破位，只要動能轉弱（較敏感，搶先離場）

這是**「慢買快賣」**的設計——寧可買晚一點確認趨勢，但要賣早一點保住獲利。非常符合**右側交易的風控思維**。

## 三、被註解的代碼 — 作者的實驗軌跡

從註解殘留可以還原作者當時的試錯過程：

| 被註解的代碼 | 原始想法 | 為什麼可能被放棄 |
|---|---|---|
| `low > close[lb] and close > out and ma_slope > 0` | 用扣抵值當支撐，畫「H」旗標 | 條件太複雜/訊號太多 |
| `condSellpre / condSell`（斜率 3%、0% 版本） | 早期賣出邏輯：MA8斜率 3% 內 + MA21斜率正 | 太依賴固定百分比，被加速度取代 |
| `result > 5`（距離大量區 5 根內） | 大量區當買進過濾 | 可能訊號太稀 |
| `ma8slope >= 0` / `ma55slope >= -0.002` | 更多斜率過濾 | 過濾太多，訊號消失 |
| `condGrwUp[1] == false`（買進的「剛轉正」限制） | 買進也要求「剛從減速轉加速」 | **買進太嚴格**，訊號太少，最終移除 |
| `plot(transprent)` | 用權重控制透明度 | 視覺實驗未完成 |

**關鍵演進故事**：
1. 作者先寫了**簡化版賣出**（用固定斜率百分比）
2. 後來發現**加速度（ma16sGrw）更好用**，改用二階導數
3. 買進原本也要「剛轉正」限制，但發現太嚴格 → **取消買進限制、保留賣出限制**（因為賣出要即時、買進可以等確認）
4. 大量區、扣抵值、多頭分級都被試過，但最終**精簡到「加速度 + 斜率 + 突破」三個條件**

## 四、整體交易哲學總結

1. **趨勢是朋友**：只用均線系統，不猜頂摸底
2. **動能比價格重要**：核心決策來自均線斜率與加速度，而非 K 線型態
3. **買賣不對稱**：買等突破確認（右側），賣看動能衰竭（提前）
4. **台股語境**：扣抵概念、紅漲綠跌的配色直覺
5. **漸進簡化**：從「很多條件」最終收斂到「最少而有效」的 3 個買進條件 + 3 個賣出條件
